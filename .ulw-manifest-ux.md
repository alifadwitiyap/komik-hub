# File-Ownership Manifest — UX deepening wave

unit: komik-hub-ux-01-03-04

## Kenapa tidak 3 lane penuh

Awalnya 04, 01, 03 semuanya terlihat independen. Ternyata tidak:

- **04 dan 01 sama-sama menyentuh `Search.tsx`** (04 di baris 33/366/536, 01 di blok fetch + state).
- **01 dan 03 sama-sama butuh tipe baru** di `types.ts` / `api.ts`.

Dua lane menulis `Search.tsx` bersamaan bukan pilihan, apa pun kemampuan merge-nya.
Yang berbahaya bukan konflik teks yang kelihatan, tapi auto-merge bersih dari dua
edit yang masing-masing menganggap edit lain tidak ada.

Resolusi: **split** untuk tipe (jadi satu owner di fase plumbing), **single-owner**
untuk `Search.tsx` (lane A memegang 04 + 01 sekaligus, karena keduanya satu file).

## Temuan di tengah jalan (file di luar rencana awal)

```
streams:
  - id: S (ditemukan saat gate surface, bukan direncanakan)
    scope: service worker mencegat panggilan fase 2
    files:
      - komiku-web/public/sw.js
    starts: after A
    verify: counter /api/stats naik 2 untuk 2 fetch ke URL sama
```

`sw.js` TIDAK ada di rencana awal. Ia muncul karena gate surface membuktikan
fase 2 tidak pernah jalan di browser: `/api/unified/search` masuk
`staleWhileRevalidate`, jadi panggilan ulang dilayani respons fase 1 yang sama
dari cache SW. Tanpa perbaikan ini, seluruh fitur dua fase tidak akan pernah
bekerja di produksi walau server dan hook-nya benar.

## Cara manifest ini diperiksa

Setelah lane kembali, `git diff --name-only` dibandingkan dengan daftar di atas.
File yang disentuh lane tapi tidak dideklarasikan = defect manifest, dilaporkan.
File yang disentuh dua lane = kegagalan yang justru ingin dicegah artefak ini.
